# コトバ

トガメの次の形。選択肢を出さず、まず自分の言葉で書かせる。

**開くとき**: `kotoba/index.html?app=x`（iOSショートカットからの入口はトガメと同じ）

## トガメとの違い

トガメは「暇つぶし／逃避／調べもの／勉強や仕事」の4択で理由を選ばせていた。選択肢は速いが、押した瞬間に考えるのをやめられる。押すだけなら理由を捏造するコストがほぼゼロなので、無意識のまま通過できてしまう。

コトバは選択肢を出さない。入力欄だけを出して、いま何をしに行くのかを自分の言葉で書かせる。言語化そのものを一拍にする。

## 通す／通さない／もう少し聞く

書かれた言葉は、その場で端末内のテーブル `entries` に1行として落ちる。列は `t, day, hour, wd, app, text, len, intent, spec, turns, verdict, opened`。`intent`（目的あり・逃避・暇・反応待ち）と `spec`（具体性0〜4）は、語彙と文の形から端末内で付ける。

判定のたびに、このテーブルを7本のSQLで叩く。「今日ここに何回書いたか」「そのうち何回実際に開いたか」「この時刻に過去14日で何回来ているか」「申告文は普段より短くないか」「同じアプリに直近どう書いたか」。AIに渡すのはこの集計結果と本人の言葉だけで、AIは次のどれかを返す。

- `pass` 言葉が具体的で、ログとも矛盾しない。通す
- `ask` 曖昧か、ログと食い違う。あと1つだけ聞き返す（既定で3往復まで）
- `block` 中身のない後付けで、ログ上も繰り返している。今回は止める

決め手にした数字を必ず1つ名指しさせている。判定画面の「何を見て決めたか」を開くと、走らせたSQLとその結果がそのまま出る。SQLタブでは自分の手で叩ける。

## AIが落ちたとき

エンドポイント未設定・上限超え・通信失敗・JSONが壊れている、のいずれでも端末内の判定に落ちる。`intent` と `spec` と今日の回数だけで pass / ask / block を決めるので、通信が切れた瞬間に素通しになることはない。

## 技術

- HTML / CSS / JavaScript（依存ライブラリなし・単一ファイル）
- localStorage（ログイン不要・端末内保存・最新500行）
- SELECT / WHERE / GROUP BY / ORDER BY / LIMIT だけを解釈する自前のミニSQL
- AIの受け口はトガメと共通（[../worker/](../worker/)）
